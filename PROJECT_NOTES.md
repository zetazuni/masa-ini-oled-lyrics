# Masa Ini — OLED Lyrics Video (Project Notes)

Reference notes for continuing development. Written from a read-through of the three project files; nothing here was compiled or run on hardware during the analysis.

## 1. What this is

A "lyric video" for **"Masa Ini, Masa Nanti dan Masa Indah Lainnya" by Nuca**, shown on the built-in OLED of a **Heltec WiFi LoRa 32 V4** and filmed with a phone (for an Instagram story). Audio is **not** played by the board. The song plays from another device and the board only shows time-synced lyrics.

Note: the built-in display is an **SSD1315 OLED (128x64, I2C)**, not an LCD. It is driven as an SSD1306 clone through U8g2.

## 2. Files

| File | Role |
|---|---|
| `MasaIni_LyricsVideo.ino` | The firmware: state machine and drawing code. Includes the lyric data from the `.h`. |
| `MasaIni_Stamper.py` | PC tool (Python + `pynput`). You play the song and tap SPACE at each lyric start. It exports a lyric table. |
| `lyrics_timestamps.h` | Generated by the stamper: `struct Lyric`, `SONG_DURATION_MS`, `lyrics[]`. `#include`d by the `.ino`. |

### Workflow
1. Edit the `LYRICS` list in `MasaIni_Stamper.py`.
2. `pip install pynput`, then `python MasaIni_Stamper.py`.
3. Press Enter, start the song and press **T** at that moment. Press **SPACE** at the start of each line. **B** undoes the last stamp, **Q** quits and exports.
4. It writes `lyrics_timestamps.h` next to the script (the `.ino` `#include`s it).
5. Flash (Arduino IDE, Heltec ESP32 board package, library **U8g2 by olikraus**).
6. Press BOOT on the board and hit play on the phone or PC at the same moment. Film. Tweak `SYNC_OFFSET_MS` if it is consistently early or late.

## 3. Hardware and pins (from the code)

| Signal | GPIO | Notes |
|---|---|---|
| OLED SDA | 17 | I2C |
| OLED SCL | 18 | I2C |
| OLED RST | 21 | |
| Vext control | 36 | Drive **LOW** to power the OLED (external 3.3 V rail). Must be done before `disp.begin()`. |
| User button | 0 | BOOT button, active LOW, `INPUT_PULLUP` |

MCU: ESP32-S3R2. Display object:
`U8G2_SSD1306_128X64_NONAME_F_HW_I2C disp(U8G2_R0, OLED_RST, OLED_SCL, OLED_SDA);`
(`_F_` = full frame buffer, 1 KB RAM.) `Wire.begin(SDA, SCL)` is also called explicitly in `setup()`. Contrast is set to 255.

## 4. Firmware architecture

### Data
```cpp
struct Lyric { const char* line1; const char* line2; unsigned long startMs, endMs; };
// in lyrics_timestamps.h:
#define SONG_DURATION_MS (178573UL)   // = last start + 6000
const Lyric lyrics[] = { ... };       // 17 entries
```
- `line2 == ""` means a single line, drawn large.
- Times are ms from the **moment BOOT is pressed** (not from the song start unless you press together).

### State machine (`enum AppState`)
`INTRO -> WAITING -> PLAYING <-> PAUSED -> DONE -> (BOOT) -> PLAYING`

| State | Screen | BOOT press does |
|---|---|---|
| INTRO | Animated title card (~6 s), then auto-advances | Start playback |
| WAITING | "Sedia untuk mula? / Tekan BOOT >>" | Start playback |
| PLAYING | Lyrics screen | Pause |
| PAUSED | Frozen frame plus blinking "II" | Resume (`songStartMs += paused duration`) |
| DONE | "Terima kasih kerana mendengar" | Replay |

### Timing
- `elapsed = millis() - songStartMs`. `findLyricIdx()` scans the table **backwards** for `startMs <= elapsed < endMs`. That is O(n) per frame, which is fine for 17 lines.
- The loop is a busy loop (no `delay`), with one `sendBuffer()` per pass.

### Lyrics screen layout (128x64)
- **y 0-9 header**: 3 bouncing note sprites (`mnotes[]`, updated every 80 ms), the "Nuca" label, and a blinking "II" when paused.
- **y 10-54 lyric zone**:
  - single line: `7x13B` bold, falls back to `6x10` if wider than 124 px, plus an underline that grows over the line's duration
  - two lines: `6x10`, centred at y=30 and y=43
  - three dots at bottom-right fill up over the line's duration
  - no active lyric: a flashing big countdown (rounded up, 5-4-3-2-1) before the next lyric, or a blinking `~ ~ ~` after the last line
- **y 57-63 progress bar**: with elapsed `MM:SS` drawn in XOR mode (`setDrawColor(2)`) so it stays visible over the fill.

### Fonts
| Font | Approx. chars/line | Used for |
|---|---|---|
| `u8g2_font_7x13B_tf` | ~18 | big single-line lyric, "Nuca" on intro |
| `u8g2_font_6x10_tf` | ~21 | two-line lyrics, waiting/done text |
| `u8g2_font_5x7_tf` | ~25 | intro title, hints |
| `u8g2_font_4x6_tf` | ~32 | header, progress time |

## 5. Current lyric timing (as in `lyrics_timestamps.h` and the `.ino`)

The first lyric starts at **99.44 s** (measured from song start). With `PRE_ROLL_MS` = 5000 the board flashes a 5-4-3-2-1 countdown after BOOT, then shows the first line. Song length is set to **178.573 s**. All 17 lines are contiguous (each `endMs` equals the next `startMs`), so there are no `~ ~ ~` gaps mid-song. The only one is the 2 s tail after the last line.

All fixed in code (not compiled or run on hardware; no `arduino-cli` was available):

| # | Issue | Fix |

| 2 | First stamp forced to 0 (files started at 99440) | Stamper now has **T** = song start (t=0). **SPACE** only stamps once the timer runs, so the first stamp is the real time of the first lyric. |

| 4 | Only start times captured | Unchanged by design (end = next start). Use an empty `""` entry in `LYRICS` for an instrumental gap. |

| 6 | Dead code | Removed `wipeTransition()`, `drawCentredY()`, unused `done` in `export()`. Header comment and footer guide rewritten. |
| 7 | Note sprites overlapped the y=9 divider | Bounce range limited to y 0-2 (sprite is 7 px tall). Speeds reduced to suit. |
| 8 | Blocking 40 ms debounce | Non-blocking (`lastBtnMs`). |
| 9 | Malay UI text vs Indonesian song | Left as is (a style choice). |
| 10 | Copyrighted lyrics in source | Left as is. Keep the repo private. |

### Changes after first hardware test
- **Pre-roll:** `PRE_ROLL_MS` (5000) in the `.ino`. Pressing BOOT now jumps the internal clock so the first lyric appears 5 s later. **Start the song at 1:34 (first lyric time minus 5 s) when you press BOOT**, since the progress bar clock shows song position. The countdown flashes a big number that rounds up (5,4,3,2,1). The old "lirik dalam Ns..." screen was removed, so keep `PRE_ROLL_MS` small (a few seconds).
- **Progress bar:** the first attempt (making the frame 7 px tall) did not fix the garbled look. The real cause was the XOR'd clock text drawn *inside* the bar: digits as tall as the bar's interior turned into stripes over the fill. The bar is now plain (frame y 58-62 + fill) and the clock `MM:SS/MM:SS` is drawn right-aligned in the header (`drawClock()`). The pause `II` moved to x=62.

- **Bar/clock zero point:** with the pre-roll, the internal clock starts at ~1:34, so the bar began mid-way. Progress and the header clock are now measured from the first lyric to the end of the song (`progressBase()`), so both start at 0 when the lyrics begin.

## 7. Ideas for continuing

- **Better sync for filming:** start playback on a serial command, a Wi-Fi/BLE trigger from the phone, or a 3-2-1 countdown on the OLED before the BOOT press takes effect.
- **Stamper improvements:** add a re-time mode for one line (nudge +/-100 ms), load lyrics from a `.txt`, and support end stamps.
- **Camera friendliness:** check for OLED flicker or banding in phone video. Try a higher I2C clock (`Wire.setClock(400000)`), a fixed frame rate (for example `delay` to about 30-60 fps), and different exposure.
- **Visual polish:** per-word or karaoke-style highlighting, wipe/slide transitions between lines (the old `wipeTransition()` was removed), and a scrolling display for long lines instead of auto-splitting.
- **Extras the board has:** LoRa radio (multi-board synchronized displays), Wi-Fi (NTP or web control), and the RGB/white LED for beat flashes.
- **Other songs:** change `LYRICS`, re-stamp, and update the title strings in `drawIntro()` and the header label.
